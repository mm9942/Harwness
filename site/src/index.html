CONCEPTUAL PATH · NOT A LIVE DEMO

Harwness is a Linux-first systems project for agents that research, write code, and carry out operational work.

A model can propose a next step. Whether that step is authorized, which resources it receives, and when its work counts as complete are separate questions. Harwness anchors these decisions in a Rust-based runtime.

01

Authority is explicit. Delegation must stay within the parent’s rights.

02

Work has state. Jobs, leases, and cancellation signals extend beyond an individual turn.

03

Success is not a text label. Verification and goal acceptance remain distinct steps.

Agents are defined.
Not just described.

Layered TOML definitions become a typed intermediate representation. Eight ordered compiler passes validate or resolve roles, rights, skills, reachable tools, models, and child definitions.

TOML→Typed IR→8 compiler passes→Artifact

A content hash binds the definition. It proves neither the author’s identity nor the safety of execution.

Implemented in sourceharw-authority

A prompt is
not a permission.

The runtime derives authority from trusted configuration and the entry point. Child contexts intersect permissions, network scope, and write scope with the parent’s constraints.

Child authority⊆Parent authority

Model providers and authority remain separate. A different channel or a more capable model does not automatically receive additional rights.

Authority and isolation are different layers.

The strongest implemented Linux job path combines cgroups, Bubblewrap, and an inner executor. The executor verifies its execution context and applies Landlock, resource limits, and reduced privileges, among other controls.

  1. 01
    Outer job executorcgroup membership before launch
  2. 02
    Bubblewrapnamespaces and restricted mounts
  3. 03
    Inner job executorLandlock · rlimits · NO_NEW_PRIVS
  4. 04
    Jobexecution within verified constraints

Requested does not mean enforced. The host, backend, and policy determine which controls are actually available. Required jobs are intended to fail when requirements cannot be met; BestEffort is not equivalent. Darwin does not offer Linux isolation parity.

What this page establishes.

A source-grounded account of selected mechanisms. Neither the full Rust workspace nor privileged host services were newly built, run, or independently audited for this overview. Implementation, integration, and evaluation remain distinct claims.

Research drafts and plans are not treated as completed features. The latest merge records maintainer-reported local validation; this website update does not reproduce those runs or establish successful remote CI. Read the merge record.

Is Harwness a language model?＋

No. Its focus is the systems layer around model-assisted work: definitions, runtime, rights, jobs, and evidence. Choosing a model provider is a separate decision and grants no additional authority.

Is this a finished production platform?＋

Harwness is in active development before version 1.0. Interfaces and configuration may change. Existing code is not the same as verified production readiness.

How can I inspect the project?＋

Start with the README at the pinned revision, follow the source links on this page, and inspect the conditions of each execution path. The earlier website is preserved in the overview archive .
