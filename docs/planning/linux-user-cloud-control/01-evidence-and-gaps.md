# Evidence and gap register

Read [the frozen references and source index](README.md#8-evidence-index) first. Labels: **O** = directly observed source/metadata; **R** = an attributed previous PR/audit report, not freshly reproduced; **T** = a proposed requirement. Priorities are relative to this program: **P0** blocks a trustworthy integration or enabling a control path; **P1** blocks the target capability; **P2** improves operations or presentation. A gap is not automatically a security vulnerability or a demonstrated production failure.

The register deliberately distinguishes library availability, application composition, configuration, enforcement, evidence transport and actual deployment. The same component can be implemented in one column and incomplete in another.

## How to close a row

A closure requires the row ID, implementation PR and exact SHA; the real producer and consumer path; relevant configuration and platform; a positive test; a refusal/loss/race test; executed commands and results; and any remaining deployment conditions. `Docs updated`, `crate exists`, `PR merged`, `port listens` and `model says complete` are not closure evidence on their own.

Newly discovered exploitable security defects must follow SECURITY.md's private reporting route. This public register is an integration/capability analysis, references already-public review gates, and intentionally does not assert new exploitability.
