## Executive delta

This audit is **not** a fresh lifecycle implementation plan. Harwness `dev` already contains executable provider-offering lifecycle logic in `harw-model-catalog/src/lifecycle.rs`, explicit enforcement in `harw-ops/src/live_model.rs`, and tests that prove rejected retired switches leave controller/persisted state unchanged.

The audit therefore records **new/remaining data and integration gaps** without claiming that unimplemented coverage exists.

## OpenAI

Official sources:
- https://developers.openai.com/api/docs/deprecations
- https://developers.openai.com/api/docs/pricing
- https://developers.openai.com/api/docs/changelog

Current Harwness already has the 2027-01-14 GPT-4o/GPT-4.1 retirement set in `bundled_lifecycles()`. The older 2026-10-23 wave is already past and should be treated as retired if any of those IDs remain configurable. The 2026-12-01 and 2026-12-11 waves remain upcoming and should be represented only for model/API surfaces Harwness actually exposes.

Pricing is **per OpenAI API offering**, not an upstream-family property. Current OpenAI pricing separates input, cached input and output, and Batch/Flex/Priority or specialized modalities can have different schedules. Lifecycle research should record the provider's official replacement first; pricing should be refreshed from the pricing page rather than inferred from family names.

## Repository-state reconciliation

Implemented on current `dev`:
- provider+model-keyed lifecycle records;
- date-only retirement windows rather than assuming a provider's midnight;
- explicit retired-model rejection with replacement hints;
- no silent model substitution;
- atomic switch tests proving failed retired choices do not mutate active state or persisted defaults;
- models.dev cache fallback and filtering of models marked `deprecated`.

Important remaining boundaries:
- the bundled lifecycle table is still a manually curated subset, so new provider notices must be added deliberately;
- direct session-driver / SDK setters are documented as outside `harw-ops` lifecycle enforcement;
- model router `rank`/`pick` currently has no productive caller; production internal-role selection occurs elsewhere;
- provider/API capability retirements such as an endpoint shutdown should not be forced into model lifecycle metadata.

## Migration / verification work

1. **Before 2026-10-31:** migrate Mistral-hosted `zai-glm-5-2` pins to `zai-glm-5-3`; keep direct Z.AI untouched.
2. Audit resolved config, internal-role pins, UIA pins and provider aliases for already-retired OpenAI/Mistral IDs.
3. Add missing upcoming OpenAI lifecycle records only for routable Harwness surfaces.
4. Validate Sonnet 5.5 replacement request semantics before migrating Sonnet 4.5 pins.
5. Decide whether session-driver and SDK model setters must share the lifecycle enforcement boundary; do not claim coverage until code/tests land.
6. Keep aliases convenience-only; persisted reproducible configuration should prefer canonical pinned IDs.
7. Preserve atomicity: lifecycle validation must happen before provider-client rebuild, controller mutation and persistence.
