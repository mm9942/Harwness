## Logik
Im Match auf `claim.scope.submitter()`: Arm `Operator { id }` mit gültiger id prüft zusätzlich
`configured_submitters.contains(id)` (exakt, keine Normalisierung) → sonst
`Err("scope: Einreicher ist kein konfigurierter MCP-Principal")`. `ChannelPeer` und ungültige Operator-id bleiben
wie bisher abgelehnt (`ApprovalActor` hat nur diese zwei Varianten, `harw-types/src/ids.rs:175-181`).
Reihenfolge unverändert: Lease/Worker → Tenant/Workspace → Einreicher (+ Config) → Eingabe-Scope. Fehlerpfad in
`execute_prompt_claim` → `JobOutcome::Failed`, vor Prompt-Parsing und Modellaufruf.
