## (a) `derive_plan_node_sandbox(inherited, contract, kind, may_write)`
- Reihenfolge: `leaves_workspace`-Ablehnung (unverändert) → Vertragsforderung ⊆ `inherited`
  (unverändert, fail closed) → `job_sandbox(JobEntry::PlanNode{kind, may_write}, inherited.workspace().canonical_root())`
  → Rechte = `node.restrict(&contract_ceiling).restrict(inherited.permissions()).permissions()`
  → Ergebnis = `inherited.restrict_with(&rechte, node.network_scope())` → `ensure_child_of(inherited)`.
- **Abweichung vom Spec-Wortlaut (bewusst):** Ergebnis wird auf `inherited` (nicht auf `node`) aufgebaut.
  Grund: `root_sandbox` bindet unter Tenant `job` / Workspace `project` (`harw-runtime/src/sandbox.rs:61-71,90-115`),
  `ensure_child_of` vergleicht `WorkspaceBinding` per `==` (`harw-sandbox/src/lib.rs:950-958`, Derive `:652`).
  `node.restrict(..)` hätte eine fremde Bindung getragen → `ensure_child_of` scheitert immer, und die
  Sandbox wäre an einen anderen Tenant gebunden. Rechte-Ergebnis identisch zum Spec
  (inherited ∩ Tabelle ∩ Vertrag); Netz = inherited ∩ Tabelle (leer).
- Aufrufer `execute_plan_node_claim`: `kind` aus `node_kind(..)`; `may_write` existierte am Aufrufer **nicht vor**
  der Ableitung (wurde erst danach aus der Sandbox gelesen). Übergeben wird jetzt
  `requests_write = !payload.contract.allowed_paths.is_empty()`; das nachgelagerte
  `may_write = sandbox.permissions().contains(WriteWorkspace)` für `profile_for_node_kind` bleibt.
- `profile_for_node_kind` unverändert.

## (b) BLOCKED
Die Config ist im Worker-Kontext nicht erreichbar:
`run_job_worker_once(store, executions, provider, transcript_root, plan_services)` →
`execute_claim(claim, input, provider, transcript_root, plan_services, control)` →
`execute_prompt_claim(claim, input, provider, transcript_root, control)` — kein `ResolvedConfig`, keine
Principal-Menge; `PlanNodeServices` ist optional und plan-spezifisch. Einreicher-Feld wäre
`claim.scope.submitter()` → `ApprovalActor::Operator { id }` (bereits in `check_prompt_claim_scope` gematcht).

Nötig (ohne Signaturänderung von `run_job_worker*` unmöglich): ein zusätzlicher Parameter, z. B.
`configured_submitters: Arc<std::collections::BTreeSet<String>>` (aus `runtime_jobs::configured_principal_ids`)
oder `config: Arc<ResolvedConfig>`, durch `run_job_worker` → `run_job_worker_once` → Closure →
`execute_claim` → `execute_prompt_claim` → `check_prompt_claim_scope`, plus Aufrufstelle in `main.rs` (serve)
und alle Test-Aufrufer von `run_job_worker_once` in `job_worker.rs`. Alternativ: Feld an `PlanNodeServices`
wäre falsch (Prompt-Jobs laufen auch mit `plan_services = None`).
