### `harw-core/src/activation.rs`

```rust
/// impl SessionActivation (Struct ab Zeile 154/155, Methode am Ende des
/// impl-Blocks, vor der schließenden `}`, Zeile ~439 nach Einfügung)
impl SessionActivation {
    pub fn intersect(&self, other: &Self) -> Self;
}
```

**Semantik (dokumentiert in Rustdoc am Code, Zusammenfassung hier):**
Gelesen: `SessionActivation` (Zeile 154-165) hat kein reines
Allow-/Denylist-Paar, sondern ein Drei-Stufen-Modell pro Werkzeugname
(`is_tool_enabled`, Zeile 233-244: `tools_disabled` schlägt
`tools_enabled_extra` schlägt `ToolProfile::allowlist()`) plus zwei
unabhängige, labelbasierte Denylists für Instructions/Context
(`instructions_disabled`/`context_disabled`, jeweils „sichtbar" = Vorgabe,
nur `disable_*` schränkt ein).

- Instructions/Context: Schnitt = Vereinigung der beiden
  `*_disabled`-Mengen (da Vorgabe „sichtbar" ist, ergibt „in mindestens
  einer Menge deaktiviert" exakt die Negation von „bei beiden aktiviert").
- Werkzeuge: `ToolName` ist ein unbegrenzter Namensraum; `ToolProfile::Full`
  bedeutet „alles sichtbar, was nicht explizit deaktiviert ist" (unbegrenzte
  Vorgabe), `Coding`/`Minimal` bedeuten „nur eine feste, endliche Liste (bzw.
  keine)". Um den Schnitt für **jeden** möglichen Namen korrekt abzubilden,
  nicht nur die in den Override-Mengen erwähnten, sammelt `intersect` zuerst
  eine endliche Kandidatenmenge (alle Namen aus beiden `tools_disabled`,
  beiden `tools_enabled_extra`, beiden `ToolProfile::allowlist()`). Für jeden
  Namen außerhalb dieser Menge fallen beide Seiten auf ihre Profil-Vorgabe
  zurück, und „beide erlauben" ist dort nur möglich, wenn beide Profile
  `Full` sind (eine endliche `Coding`-Allowlist erlaubt laut Konstruktion nie
  einen Namen außerhalb ihrer selbst, `Minimal` erlaubt nichts außerhalb von
  Overrides). Ergebnis-Konstruktion:
  - Beide `Full` → Ergebnisprofil `Full`, mit `tools_disabled`-Eintrag für
    jeden Kandidatennamen, der nicht von beiden erlaubt ist.
  - Sonst → Ergebnisprofil `Minimal`, mit `tools_enabled_extra`-Eintrag für
    jeden Kandidatennamen, der von beiden erlaubt ist.
  Damit stimmt `result.is_tool_enabled(name)` für **jeden** `name`
  (nicht nur Kandidaten) mit `self.is_tool_enabled(name) &&
  other.is_tool_enabled(name)` überein — monoton, kommutativ, idempotent
  (durch Tests belegt, siehe unten).
