## Semantik-Entscheidungen (dokumentiert im Rustdoc)

- `OpenMode` validiert wie `std::fs::OpenOptions` (`InvalidInput`): kein Zugriff; create/create_new/truncate ohne Schreiben; truncate+append. Immer `NOFOLLOW | CLOEXEC`. `create_mode()` ist ohne create/create_new **leer**, weil `openat2` einen Modus ≠ 0 ohne `O_CREAT` mit `EINVAL` ablehnt.
- `open_nofollow`/`open_dir_nofollow`: nur letztes Glied symlinkfest (Eltern werden normal aufgelöst). `open_dir_nofollow` öffnet `O_RDONLY|O_DIRECTORY` (lesbar für readdir/fsync).
- `open_beneath`: **Vorvalidierung auf beiden Pfaden** — leer, absolut, jede `..`-Komponente → `InvalidInput` (auch nicht ausbrechendes `a/../b`), damit openat2- und Fallback-Semantik identisch sind. `.` wird ignoriert, reines `.` öffnet die Wurzel. Linux: `openat2(BENEATH|NO_SYMLINKS|NO_MAGICLINKS)`, `EAGAIN` ≤16× wiederholt, `EINTR` via `retry_on_intr`. Fallback bei `ENOSYS` **und `EPERM`** (seccomp älterer Container-Runtimes; Fallback ist gleich streng, echte Rechtefehler kommen dort erneut). Fallback: Zwischenglieder `openat(O_PATH|O_DIRECTORY|O_NOFOLLOW|O_CLOEXEC)` (Nicht-Linux `O_RDONLY` statt `O_PATH`) + `fstat`-Prüfung auf S_IFDIR, letztes Glied `openat(flags|O_NOFOLLOW)`.
- `write_atomic`: Elternverzeichnis einmal per `openat(CWD, parent, O_RDONLY|O_DIRECTORY|O_CLOEXEC)` (Eltern-Symlinks werden gefolgt — nur das letzte Glied ist symlinkfest), danach alles dirfd-relativ. Temp `.<präfix>.<pid:x>.<zähler:x>.<nanos+attempt:x>.tmp`, Präfix auf `255 − 1 − suffix` Bytes gekürzt, `O_WRONLY|O_CREAT|O_EXCL|O_NOFOLLOW|O_CLOEXEC` Modus 0600, bis 64 Versuche bei `EEXIST`. Dann `write_all`, `fchmod(mode & 0o7777)` (umask-unabhängig), `sync_all`, `renameat` (ersetzt Ziel-Symlink als Eintrag). Fehler vor/beim rename → `unlinkat` der Tempdatei best-effort, Ziel unverändert. `fsync_dir == true`: `fsync(dirfd)` **nach** rename; Fehler wird zurückgegeben (Inhalt dann schon sichtbar, Dauerhaftigkeit nicht garantiert), `EINVAL` (FS ohne Dir-fsync) ignoriert. `fsync_dir == false`: kein Dir-fsync. `InvalidInput` wenn letztes Glied nicht `Normal` (`/`, `..`).
- `ensure_private_regular`: `File::metadata()` (fstat): nicht regulär → `InvalidInput`; `uid != geteuid()` oder `mode & 0o077 != 0` → `PermissionDenied`.
- `walk_beneath`: Wurzel per `open_dir_nofollow`, nicht selbst gemeldet. DFS-Vorordnung, Namen je Verzeichnis bytewise sortiert. Typ via `statat(AT_SYMLINK_NOFOLLOW)`; Unterverzeichnisse per `openat(parentfd, name, O_RDONLY|O_DIRECTORY|O_NOFOLLOW|O_CLOEXEC)` + `fstat` (S_IFDIR-Check, (dev,ino) in globalem `visited`-Set; bereits gesehen → still nicht absteigen). `len`: st_size für File/Symlink, 0 für Dir/Other. Tiefe: Kinder der Wurzel = 1; Verzeichnis auf Tiefe `d` wird nur betreten wenn `d < max_depth`, sonst `DepthLimit` (Iteration läuft weiter; auch bei leerem Verzeichnis). `max_depth == 0` → nichts, `DepthLimit`. `max_entries` zählt gelieferte Items inkl. Fehler; `EntryLimit` nur, wenn danach noch ein Eintrag käme (genau N Einträge → `None`). Deadline (`now >= deadline`) vor jedem Item und alle 64 readdir-Einträge → `Deadline`. EntryLimit/Deadline beenden und überschreiben DepthLimit. Speicher je Verzeichnis: BinaryHeap der `rest+1` kleinsten Namen (deterministisch trotz Begrenzung). Fehler-Items tragen errno, keinen Pfad.

## Compile-/Lint-Risiken (nicht verifiziert, da kein cargo check erlaubt)

- `Cargo.lock`: Eintrag `harw-fsutil` (Zeile ~2527) hat noch keine `dependencies`; nächster nicht-`--locked` Cargo-Lauf ergänzt `rustix 1.1.4`/`tempfile` (beide bereits im Lock). Mit `--locked` würde es scheitern.
- `clippy -D warnings` (Makefile): `dev_ino` nutzt `as u64` mit `#[allow(clippy::unnecessary_cast, clippy::cast_sign_loss)]` (Feldtypen archabhängig); `remove_temp` nutzt `let _ =` bewusst. Nicht-Linux-`mode_from_bits` mit `as RawMode` + allow.
- Borrow-Stellen (NLL, disjunkte Felder) in `WalkBeneath::next`/`enter` und `current.as_ref().map_or(root, AsFd::as_fd)` in `open_beneath_componentwise` — nach Lesen plausibel, nicht kompiliert.
- Konstantenmuster `Err(Errno::NOSYS | Errno::PERM)` setzen strukturelle Gleichheit von `Errno` voraus (von rustix selbst in `retry_on_intr` `src/io/errno.rs:70` so verwendet).
- rustfmt nicht verfügbar → mögliche kleine Formatabweichungen.

## Plattformhinweise

- Unix-only (std::os::unix). Linux: openat2 + Fallback; `O_PATH` für Zwischenglieder. Nicht-Linux: nur komponentenweise, `O_RDONLY` für Zwischenglieder (nur-`--x`-Verzeichnisse dort nicht passierbar).
- Kernel < 5.6 bzw. seccomp-EPERM → Fallback (Tests decken den Fallback direkt über `open_beneath_componentwise` ab).
- aarch64-Pi: O_NOFOLLOW ausschließlich über `OFlags::NOFOLLOW` (0o100000); keine Zahlkonstanten im Crate.
- `ensure_private_regular` und `walk` lesen `st_*` über std-`MetadataExt` bzw. rustix-`Stat`; `len` für Verzeichnisse bewusst 0 (FS-abhängige Größen).
