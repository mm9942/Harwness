## 1. `GateReport::is_green` (G-102)

`xtask/src/gates.rs:59-64`: `is_green()` verlangt jetzt
`self.checked > 0 && self.violations.is_empty()` statt nur
`self.violations.is_empty()`. `run()` (`gates.rs:96-129`) selbst brauchte
keine Anpassung — es filtert bereits über `!r.is_green()`.

**Tests** (`xtask/src/gates.rs`, neues `#[cfg(test)] mod tests`):
- `test_is_green_empty_report_is_red` — `checked: 0, violations: []` ⇒ rot.
- `test_is_green_checked_without_violations_is_green` — `checked: 5, []` ⇒
  grün.
- `test_is_green_with_violations_is_red_regardless_of_checked` — Verstöße
  bleiben rot, unabhängig von `checked`.

## Risiken / offene Punkte

1. **`is_green`-Semantikwechsel bricht fremde Tests (Folgearbeit, siehe
   unten).** Die genannten drei Dateien enthalten mindestens die Tests
   `gate_edges.rs::test_evaluate_empty_graph_is_green_with_zero_checked` und
   `gate_privileges.rs::test_evaluate_empty_graph_is_green_with_zero_checked`
   (Namen laut `grep`), die einen leeren Graphen (`checked == 0`) explizit
   als grün erwarten — das kippt jetzt zwangsläufig auf rot. Nicht in
   meiner Zuständigkeit angefasst.
2. **`cargo fmt -p xtask -- --check` / `-p harw -- --check` nicht
   ausführbar.** `rustfmt` ist auf dieser Maschine nicht installiert
   (`cargo fmt` ⇒ „no such command: fmt"). Formatierung wurde von Hand nach
   dem Stil der umgebenden Datei gehalten (4-Leerzeichen-Einrückung,
   Zeilenlänge ~100), aber nicht mit dem vorgeschriebenen Werkzeug verifiziert.
3. **`Cargo.lock` nicht regeneriert.** `harw`s `[[package]]`-Eintrag in
   `Cargo.lock` listet weiterhin `cargo_metadata` als Abhängigkeit und noch
   nicht `toml` (`Cargo.lock:1841-1861`) — `cargo generate-lockfile`/
   `cargo build` sind mir verboten. `toml` selbst ist bereits im Lockfile
   auflösbar (siehe oben), sodass ein regulärer, nicht-`--locked`-Build die
   Kante beim nächsten Lauf automatisch nachträgt; bis dahin ist das Manifest
   und das Lockfile inhaltlich (nicht literal) konsistent.
4. **`toml`-API nur über docs.rs verifiziert, nicht gegen lokalen
   Quellcode.** Siehe Abschnitt 3 oben — kein `~/.cargo/registry/src` in
   dieser Sandbox vorhanden. Empfehlung: vor dem ersten `cargo test -p harw`
   kurz gegenprüfen, dass die zitierten Methoden exakt so heißen (die
   API ist seit toml 0.5 stabil in dieser Form, das Risiko einer Abweichung
   wird als gering eingeschätzt).
5. Keine `cargo check/build/test/clippy` ausgeführt (verboten). Alle
   Änderungen sind durch Lektüre, `cargo metadata --offline --no-deps` und
   manuelles Nachrechnen der Testlogik gegen die echten Workspace-Daten
   geprüft, nicht durch einen tatsächlichen Testlauf.
