## Befund (vor der Änderung)

`diff` war `model_tool(readonly, approval = "none")` und damit in
`harw-registry-defaults/src/lib.rs` `AUTO_APPROVED_TOOLS` (Zeile ~105, dort per
Namensliteral `"diff"` — von mir nicht verändert, siehe „Parallel-Hinweis“ unten).
Die Operation rief `ShellToolProvider::new().executor(...)` **direkt** auf
(`diff.rs:159-169` alt) und baute das Kommando als rohen `sh -c`-String
`git diff --no-ext-diff --no-color [--stat] -- '<path>'`. `git diff` wertet dabei
repo-lokale Konfiguration/Attribute aus, die der Aufrufer über einen einzigen
zuvor genehmigten `fs.write` auf `.git/config`/`.gitattributes` präpariert haben
kann: `diff.<treiber>.textconv`, `core.fsmonitor` (Hook), `diff.external`/
`GIT_EXTERNAL_DIFF`. Zusätzlich ließ `shell_quote_path` jedes `path` durch, das
nicht mit `/` beginnt oder eine `..`-Komponente enthält — git-Pathspec-Magie
(`:/`, `:(top)…`, `:(glob)…`, `::…`) blieb also nutzbar und kann den Diff über
die Workspace-Grenze hinaus erweitern, wenn die Sandbox ein größeres Repo sieht.

## Änderung

1. **Kommando-Härtung** (`build_git_diff_plan`/`render_shell_command`/`shell_quote`,
   `diff.rs:56-193`): reine Hilfsfunktion `build_git_diff_plan(&DiffArgs) -> Result<GitDiffPlan, OpError>`
   liefert `argv`/`env` als Datenstruktur (kein String, keine I/O). `render_shell_command`
   quotet **jedes** Token einzeln POSIX-safe (`'…'`, `'` → `'\''`) und rendert erst dann den
   einen `command`-String für `shell.exec`:
   ```
   GIT_CONFIG_NOSYSTEM='1' GIT_CONFIG_GLOBAL='/dev/null' GIT_TERMINAL_PROMPT='0' \
   'git' '-c' 'core.fsmonitor=' '-c' 'core.hooksPath=/dev/null' '-c' 'diff.external=' \
   '-c' 'core.pager=cat' '--no-pager' 'diff' '--no-textconv' '--no-ext-diff' '--no-color' \
   ['--stat'] ['--' ':(literal)<path>']
   ```
   Deckt genau die im Auftrag verlangten Flags/Env ab (fsmonitor, hooksPath, diff.external,
   pager, `--no-textconv`, `--no-ext-diff`, `GIT_CONFIG_NOSYSTEM=1`, `GIT_CONFIG_GLOBAL=/dev/null`,
   `GIT_TERMINAL_PROMPT=0`).
2. **Pathspec-Magie** (`validate_relative_pathspec`, `diff.rs:149-172`): lehnt leer, NUL,
   führendes `/`, `..`-Komponente **und neu führendes `:`** ab (deckt `:/`, `:(top)…`,
   `:(glob)…`, `:(exclude)…`, `::…`). Jeder verbleibende Pfad wird als `:(literal)<pfad>`
   gebunden — git interpretiert danach keine weitere Magie in `<pfad>`.
3. **Approval**: `model_tool(readonly, approval = "none")` → `model_tool(readonly,
   approval = "always")` (`diff.rs:253`). `readonly: true` unverändert (git diff mutiert
   den Workspace nicht) — nur die Genehmigungsachse ändert sich, weil weiterhin ein
   Prozess gestartet wird. `web(...)` bewusst **unverändert** gelassen (`approval = "none"`),
   da der Auftrag explizit nur die ModelTool-Fläche nennt; siehe „Offene Risiken“.
4. Moduldoku (`diff.rs:1-42`) auf den neuen Ablauf umgeschrieben (Sicherheitsbegründung
   pro Flag/Env-Variable, Verweis auf die fehlenden Argv/Env-Felder von `shell.exec`).

## Parallel-Hinweis (für W1-05)

`harw-registry-defaults/src/lib.rs` `AUTO_APPROVED_TOOLS` enthält weiterhin das
Namensliteral `"diff"` (von mir **nicht** verändert — außerhalb meiner erlaubten
Dateien). Das ist die zweite Hälfte von F-022/G-027: eine Registry-Allowlist prüft
Tool-*Namen*, nicht `ApprovalPolicy`; solange `"diff"` dort steht, kann ein
Aufrufer, der die Allowlist statt der `OperationMeta` konsultiert, weiterhin von
Auto-Approval ausgehen. Diese Änderung hier macht `ApprovalPolicy::Always` für
jeden Aufrufer verbindlich, der `OperationMeta`/`Surface::ModelTool` tatsächlich
auswertet; das Entfernen von `"diff"` aus `AUTO_APPROVED_TOOLS` ist laut Auftrag
Aufgabe von **W1-05** (parallel, andere Datei).

## Offene Risiken / nicht behoben

- **Nicht kompiliert, nicht getestet** (Verbot). Manuell geprüft: Typen, Trait-Bounds
  (`String: PartialEq<&str>`, Slice-vs-Array-`PartialEq` für die Argv-Tail-Assertions),
  Makro-Grammatik (`model_tool(readonly, approval = "always")` exakt wie
  `harw-macros/src/operation.rs`-Tests), Struct-Namensableitung (`DiffOperation`).
  `cargo metadata --offline --no-deps --format-version 1` läuft fehlerfrei (Exit 0),
  prüft aber keine Typen.
- **Web-Fläche** (`/api/diff`, GET) bleibt `approval = "none"` — laut `w4-ops-rest.md`
  V4/O3 dieselbe Angriffsfläche wie das ModelTool, nur über HTTP statt Modell-Tool-Call.
  Auftrag nennt explizit nur die ModelTool-Fläche; nicht in meinem Scope geändert.
  Empfehlung für eine Folgewelle: `web(path = "/api/diff", readonly, approval = "always")`
  oder eine explizite Begründung, warum Web-GET-Zugriff auf einen Prozessstart
  genehmigungsfrei bleiben darf.
- **`shell.exec` hat kein Argv/Env-API** (`exec.rs:127-134`): Die geforderte Env wird
  deshalb als Shell-Zuweisung im `command`-String simuliert, nicht als echte
  Prozessumgebung. Funktional äquivalent für `/bin/sh -c` (POSIX-Zuweisung vor argv[0]
  gilt nur für den einen Befehl), aber architektonisch eine Notlösung; sauberer wäre ein
  `env: BTreeMap<String,String>`-Feld an `ShellExecArgs` (außerhalb meiner erlaubten
  Dateien, Hinweis für höhere Wellen/`harw-tool-shell`-Owner).
- `git`-Pfad wird weiterhin über `PATH` in der bwrap-Sandbox aufgelöst (B7 in
  `w3-tool-fs-shell.md`) — unverändert, nicht Teil dieses Tickets.
- Kein Schutz gegen ein Repo, dessen `.git` **außerhalb** des Workspace liegt, aber von
  der Sandbox lesbar ist (Discovery-/Mount-Frage, nicht `diff.rs`).
