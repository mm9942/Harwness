## 2. `harw-tui/src/sanitize.rs` (neu)

Eine Stelle entscheidet, welche Zeichen in einen `Span` dürfen.

```rust
pub(crate) const ESC_SEQUENCE_MARKER: &str = "⟨ESC⟩";
pub(crate) fn sanitize_display(text: &str) -> String;        // mehrzeilig, ESC-Sequenzen entfernt
pub(crate) fn sanitize_inline(text: &str) -> String;         // einzeilig,  ESC-Sequenzen entfernt
pub(crate) fn sanitize_reveal(text: &str) -> String;         // mehrzeilig, nichts wird verschluckt
pub(crate) fn sanitize_reveal_inline(text: &str) -> String;  // einzeilig,  nichts wird verschluckt
pub(crate) fn is_invisible_format_char(c: char) -> bool;
```

Intern: `enum LineMode {Multiline, Inline, Marked}`, `enum EscapeMode {Strip, Reveal}`,
`fn sanitize_with(...)`, `fn escape_sequence_len(&[char]) -> Option<usize>`, `fn push_marker`.

Regeln:
- **ESC-Sequenzen**: CSI (`ESC [` Param 0x30–0x3F / Zwischen 0x20–0x2F / Ende 0x40–0x7E),
  Zeichenketten-Sequenzen (`ESC ] | P | X | ^ | _` bis BEL, U+009C oder `ESC \`;
  ein anderes `ESC` beendet sie davor, wie in xterm), `ESC nF` und zweistellige
  `ESC Fp/Fe/Fs` (u. a. `ESC c` = Reset). Im *Strip*-Modus vollständig entfernt und
  durch `⟨ESC⟩` ersetzt. **Unvollständige Sequenzen werden nie bis zum Textende
  verschluckt** (sonst ließe sich der Rest verstecken) — nur das `ESC` wird markiert.
  Im *Reveal*-Modus wird **nichts** entfernt (Freigabe: was ausgeführt wird, muss
  lesbar sein).
- **C0/C1** (`char::is_control`): `⟨U+XXXX⟩`. Ausnahmen: `\n` bleibt mehrzeilig,
  `\t` → vier Leerzeichen (ein rohes Tab verschöbe die Terminalspalte gegen ratatuis
  Zellmodell), `\r\n` → `\n`; alleinstehendes `\r` im Reveal-Modus markiert.
- **Unsichtbare Formatzeichen**: Pflichtumfang U+202A–202E, U+2066–2069, U+200E/200F,
  U+061C, U+200B–200D, U+2060, U+FEFF; zusätzlich U+2028/2029, U+2061–2064,
  U+206A–206F, U+00AD, U+034F, U+180E, U+115F/1160/3164/FFA0, U+FFF9–FFFB und
  **U+E0000–E007F** (Tag-Zeichen, „ASCII-Schmuggel").
- **Ausgabe-Invariante**: kein `is_control()`-Zeichen außer `\n` (nur mehrzeilig),
  kein `is_invisible_format_char`.

Bekannte, bewusste Nebenwirkung: Emoji-ZWJ-Sequenzen werden als
`👨⟨U+200D⟩👩` zerlegt dargestellt (U+200D ist Pflichtumfang).

Tests (`sanitize.rs`): Tabelle mit 36 Fällen (CSI-Farbe/Cursor/privat, OSC 52 mit
BEL/ST/C1-ST, OSC 0, OSC 8, DCS, APC, `ESC c`, `ESC ( B`, unvollständige OSC/CSI,
lone ESC, BEL/NUL/BS/DEL, C1 CSI/NEL, alle Bidi-Varianten, ZW, BOM, Tag-Zeichen,
U+2028, `\n`/CRLF/CR/Tab, unveränderte Unicode-Texte) plus Inline-, Reveal-,
Reveal-Inline-Tests und ein Sweep über U+0000–U+00A0, U+2000–U+206F, U+FEFF,
Tag-Zeichen gegen die Ausgabe-Invariante.

`ApprovalPromptCell` behält **Felder und Signaturen unverändert**
(`tool_name`, `arguments_raw`, `decision`, `apply_decision`) — bewusst, weil
`app.rs`-Tests außerhalb des erlaubten Bereichs (`app.rs:5600/5636`) sie per

Darstellung einer offenen Frage:

```text
⚠ Freigabe erforderlich: fs.write · path: "/home/u/.bashrc"
  content:
  │ erste Zeile
  … 12 weitere Zeilen ausgeblendet — [v] vollständig anzeigen
  [y] freigeben · [n] ablehnen · [v] vollständig anzeigen
```

- Hauptargument (`fs.write` → `path`, `shell.exec` → `command`, sonst
  `command`, ersatzweise `path`) steht **in der ersten Zeile** und wird **nie**
  eingeklappt; der vollständige Befehl bzw. Pfad ist immer sichtbar.
- Übrige Argumente in Objektreihenfolge; einzeilige Zeichenketten in
  Anführungszeichen mit `"`/`\`-Escaping (eindeutige Grenzen), mehrzeilige mit
  Randmarke `│ ` je Zeile — ein Wert kann so keine `key:`- oder Tastenzeile
  vortäuschen.
- Nichts wird still gekürzt: über acht umgebrochene Zeilen hinaus nennt eine
  Hinweiszeile die Zahl der ausgeblendeten Zeilen; `v` klappt auf/zu.
- Ohne JSON-Objekt (Array, Skalar) wird der Rohtext als `Argumente: …` gezeigt
  (das ist auch das Verhalten der `ApprovalPromptCell` ohne Ansicht,
  `ApprovalDetail::Full`, dann ohne `[v]`-Hinweis).

## 5. `approval.rs` — `review` ist seiteneffektfrei

```rust
fn review<'a>(&'a self, call: &'a ToolCall) -> ExtFuture<'a, ApprovalDecision> {
    let decision = if !self.scope.requires_approval(call.name.as_str()) {
        ApprovalDecision::Allow
    } else if self.prompt_tx.is_closed() {
        ApprovalDecision::Deny(REASON_PROMPT_UNDELIVERABLE.to_owned())
    } else {
        ApprovalDecision::AskUser(ItemId::new())
    };
    Box::pin(async move { decision })
}
```

- Kein `open_prompt`, kein Senden, kein Eintrag in `pending`. Der tote Kanal
  wird **lesend** geprüft (`UnboundedSender::is_closed`), Ablehnung bleibt der
  Default.
- Das Anzeigen übernimmt unverändert `ApprovalDriver::resolve`
  (`approval.rs`, Aufruf aus `drive_to_completion`): `has_pending` ist jetzt
  immer `false`, also stellt der Treiber die Frage über `open_prompt` aus dem
  vom Kern festgehaltenen `PendingApproval` — **eine** Frage pro Pause.
- Verhaltensgewinn: Bei der Aggregation in `check_approval` (`Deny` >
  `AskUser` > `Allow`) und in `preflight_approvals` entstanden bisher Fragen,
  die niemand beantwortet (verworfene `AskUser`-ID) oder die trotz `Deny` eines
  späteren Handlers angezeigt wurden. Produktiv läuft der Handler im Scope
  `Deferred` (immer `Allow`) — die Änderung betrifft dort nichts, schließt aber
  die Lücke für `NamedTools`/`AllTools`.
- **Nicht** geändert: `open_prompt`, `await_resolution`, `ApprovalDriver`,
  Timeouts, Abbruchgrenze. `ApprovalHandlerKind::Interactive` zu überschreiben
  bleibt Folgearbeit (W0B-07 Punkt 3; der Typ ist nur unter
  `harw_extension_api::contributors::` erreichbar).

### Sichtbarkeitsprüfung — bewusste Grenze, Folgearbeit für D5

Verfügbar ist im Bereich nur `app.scroll` (`is_at_tail`) und die zuletzt
gerenderten Zeilenzahlen. Geprüft wird deshalb „die Ansicht steht am Ende der
Historie" — dort steht die Frage als jüngste Zelle. **Nicht** geprüft wird, ob
die Frage höher ist als der Viewport oder ob nach ihr noch Zellen angehängt
wurden (im Pausenzustand die Ausnahme). Eine exakte Prüfung braucht die
Zeilenposition der Zelle im gewrappten Gesamtpuffer; die entsteht erst in
`render_viewport` (außerhalb dieses Bereichs). **Folgearbeit D5:** Zeilenbereich
der offenen Freigabezelle beim Rendern mitschreiben und
`classify_armed_approval_key(..., question_visible)` daraus speisen; die reine
Funktion ist dafür bereits vorbereitet (Parameter existiert).
