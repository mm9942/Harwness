## Semantik

### Trust-Store (`<home>/trusted-projects.toml`)
- Format `version = 1` + `[[project]] canonical_root/owner_uid/digest`; `deny_unknown_fields`.
- Laden: `open_nofollow(read_only)` → `NotFound` = leer; sonst `ensure_private_regular` (Eigentümer = euid,
  `mode & 0o077 == 0`), ≤ 1 MiB, UTF-8, Version 1, Root absolut, Digest `blake3:` + 64 Hex klein, kein doppelter
  Root – sonst `HomeError::TrustStore`/`Io`, **nie** stille Leerannahme.
- Schreiben: `write_atomic(path, …, AtomicWriteOptions::private())` (0600, Dir-fsync). Fehlendes Home wird mit 0700 angelegt.
- `trust_project`: `canonicalize(root)` → Digest → UID (`symlink_metadata(canonical).uid()`) → upsert → save.
- `untrust_project`: Schlüssel `canonicalize(root)`, bei `NotFound` der Pfad wie übergeben; speichert nur bei Entfernung.
- `project_trust_status`: kein Eintrag → `Untrusted` (Projekt wird dann gar nicht gelesen); UID abweichend/unlesbar
  → `Changed`; Digest gleich → `Trusted`; Digest verschieden **oder jeder Digest-Fehler** → `Changed` (fail-closed ohne Startabbruch).

### Digest
- Quelle: `<root>/.harw`. `.harw` Symlink/Nicht-Verzeichnis → `UntrustableProject`; fehlt → Digest der leeren Menge.
- Einzeldateien `config.toml`, `auth.toml`, `.env`: `symlink_metadata` muss reguläre Datei sein, Inhalt über
  `open_beneath(fd(.harw), name, read_only)`.
- Verzeichnisse: `walk_beneath(<.harw>/<dir>, {depth 16, entries 10 000, deadline 10 s})`; `File` → Inhalt per
  `open_beneath(fd(.harw), "<dir>/<rel>")` (kein Symlink in **irgendeinem** Glied), `Dir` übersprungen,
  `Symlink`/`Other` → `UntrustableProject`, `walk.stopped().is_some()` → `UntrustableProject`.
- Grenzen: 4 MiB je Datei, 64 MiB gesamt → `UntrustableProject`.
- Hash: `blake3::Hasher` über `b"harw-project-trust/v1\0"`, `u64le(anzahl)`, dann global bytewise nach relativem Pfad
  sortiert je `u64le(len pfad) ‖ pfad ‖ u64le(len inhalt) ‖ inhalt`; Ausgabe `blake3:<to_hex>`.
- **Abweichung (Obermenge) zur Vorgabe:** zusätzlich `models/**`, `skills/**`, `channels/**`. Begründung: diese
  Verzeichnisse lädt `discover_config` aus einem vertrauten Layer (Channel-Bindungen mit Token-Refs/Webhook-Adressen,
  Skill-Instruktionen, Modell→Provider-Routing); ohne sie könnte ein freigegebenes Repo nach der Freigabe z. B. einen
  Telegram-Channel ergänzen, ohne `Changed` auszulösen. Strenger, nie lockerer.
- Symlinks werden **nie** gefolgt und können keine Freigabe tragen, weil `discover_config` (std `read_to_string`)
  ihnen folgen würde – ein Digest über den Link wäre also nicht der geladene Inhalt.

### `config_layers_report`
- Layer `[home, profile_dir(active)]` immer. `<cwd>/.harw` (cwd = `std::env::current_dir()`, bei Fehler kein Repo-Layer)
  nur, wenn `is_dir()` und kanonisch ≠ `home` und ≠ Profilverzeichnis (→ `status: None`, kein Trust-Lookup).
- `project_trust_status(home, cwd)`: `Trusted` → `.harw` wird als letzter Layer (absolut) angehängt; sonst
  `untrusted_repo = Some(<cwd>/.harw)`, `status = Some(Untrusted|Changed)`.
- Interner testbarer Kern `config_layers_report_in(home, profile, cwd: Option<&Path>)` ohne Env-Zugriff.
