## Änderungen im Detail

1. **DELETE nur durch Eigentümer (F-047/A3).** `delete(request, state, principal_key: &str)`.
   Nachschlagen mit serverseitigem `VERSION`; unbekannt / abgelaufen / fremder Principal
   → identisches `404` ohne Body. Erst beim Eigentümer wird der Client-Protokoll-Header
   geprüft (`400` bei Abweichung), damit ein falscher Header die Existenz fremder
   Sessions nicht verrät. Fehlende Header weiterhin `400` (sessionunabhängig).
2. **Body-Limit (F-046/L1).** Neu `read_limited_body<B: Body<Data = Bytes>>` mit
   `Limited::new(body, MAX_BODY_BYTES)` (64 KiB); `LengthLimitError` → `413`, sonstige
   Body-Fehler → `400`. `size_hint`-Vorprüfung für `Content-Length` bleibt; die
   nachgelagerte, nach unbegrenztem `collect` wirkungslose Längenprüfung entfällt.
3. **SSE-Frames (R4).** Neu `fn sse_frame(event: &str, data: &str) -> Bytes` mit echten
   `\n`; `lifecycle`- und `lagged`-Frames nutzen ihn.
4. **PrincipalRegistry (F-069/A1).** `type PrincipalRegistry = HashMap<..>` →
   `#[derive(Debug, Clone, Default)] pub struct PrincipalRegistry`:
   ```rust
   pub fn new() -> Self;
   pub fn try_insert(&mut self, principal_key: String, principal: McpPrincipal)
       -> Result<(), DuplicatePrincipalId>;          // Duplikat abgewiesen, erster Eintrag bleibt
   pub fn insert(&mut self, principal_key: String, principal: McpPrincipal); // Kompatibilität, fail-closed
   pub fn get(&self, principal_key: &str) -> Option<&McpPrincipal>;
   pub fn len(&self) -> usize;
   pub fn is_empty(&self) -> bool;
   #[derive(Debug, Clone, PartialEq, Eq)]
   pub struct DuplicatePrincipalId { pub principal_key: String } // + Display, Error
   ```
   `insert` existiert nur, damit `harw-cli` (fremde Datei) weiter kompiliert
   (`registry.insert(..);`, `registry.get("..")` in Tests). Es überschreibt **nicht** mehr:
   Bei Duplikat wird die ID entfernt und dauerhaft gesperrt (`get` → `None`, leerer
   Tool-Katalog, keine Tool-Aufrufe), Warnung nur mit ID auf stderr. Kein `#[deprecated]`,
   weil `make clippy-tests` mit `-D warnings` sonst `harw-cli` bräche.
   Eigene Aufrufer (Tests in `transport.rs`) auf `try_insert(..).expect(..)` umgestellt.
5. **Fehler-Redaktion (R12).** `supervisor_error_response`: `JobStore(_)` → Client erhält
   nur `"job was not found"` (`JobNotFound`, ohne ID) bzw. `"durable job operation failed"`;
   volles `Display` (inkl. absoluter Pfade, `CorruptJob.detail`) nur per `eprintln!`
   (Crate hat keine `tracing`-Dep; `Cargo.toml` ohne Owner). `NotAuthorized` und
   `InvalidSubmission` unverändert (pfadfreie, feste Texte aus `supervisor.rs`).

## Tests (alle in `transport.rs`)

Über echten Loopback-TCP (`127.0.0.1:0`, `serve_until`):
- `oversized_bodies_are_rejected_with_413_even_when_chunked` – chunked exakt 64 KiB
  (gültiges JSON, Leerzeichen-Padding) → `200`; chunked 64 KiB + 1 Byte (letzter
  1-Byte-Chunk) → `413`; chunked 256 KiB → `413`; `Content-Length` > Limit → `413`.
- `foreign_delete_is_indistinguishable_from_unknown_session_and_keeps_it` – fremdes
  DELETE (richtige und falsche Version) und unbekannte ID → `404`, byteidentisch bis auf
  `date`; A kann danach `tools/list` (`200`); Eigentümer: falsche Version `400`, `204`,
  erneut `404`.
- `initialized_get_streams_bounded_lifecycle_events` (angepasst) – liest genau einen
  HTTP-Chunk und vergleicht **exakte Bytes** mit
  `format!("event: lifecycle\ndata: {}\n\n", serde_json::to_string(&event))`
  (unabhängig von `sse_frame` gebaut); zusätzlich kein literales `\` `n`.
- `duplicate_principal_ids_never_inherit_foreign_rights_over_tcp` – `try_insert`-Duplikat
  abgewiesen, erster Eintrag (ReadOwn) wirkt, kein `harw_job_cancel`; `insert`-Duplikat →
  `"tools":[]`.

Unit:
- `sse_frames_use_real_line_breaks` (lagged-Frame exakt).
- `principal_registry_rejects_duplicate_ids_and_keeps_first_entry`.
- `principal_registry_compat_insert_disables_duplicate_ids_fail_closed`.
- `store_error_details_are_redacted_for_clients` (CorruptJob mit Pfad, Io mit Pfad,
  JobNotFound ohne ID, NotAuthorized unverändert).
- `tools_are_capability_filtered_and_authorized_end_to_end` nutzt jetzt `try_insert`.

Risiko Test-Flakiness: Beim 413 schließt hyper mit ungelesenem Rest → ggf. RST.
Der Helfer `round_trip_bytes_lenient` ignoriert Schreibfehler und liest bis EOF/Fehler;
bereits empfangene Antwortbytes bleiben unter Linux lesbar.
