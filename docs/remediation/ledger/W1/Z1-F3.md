## 1. R1-01 / R1-02 — `render_shell_output` wertet Kürzung statt Fehler

Beleg für die JSON-Semantik: `exec.rs:443-465` (`completed_output`) —
`killed_by_output_limit: true` wird ausschließlich mit `exit_code: -1`
zurückgegeben (`exec.rs:395-403`, `status.and_then(|s| s.code()).unwrap_or(-1)`
nach SIGKILL); `truncated` kann daneben auch bei einem echten, ungleich-null
**oder** null Exitcode gesetzt sein, wenn `truncate_combined_output` das
Byte-Budget nachträglich kappt, ohne dass der Prozessbaum getötet wurde
(`exec.rs:450-455`, Test `small_output_over_cap_is_truncated`).

`diff.rs::render_shell_output` (~Z. 213) liest jetzt zusätzlich `truncated`
und `killed_by_output_limit` (`Value::as_bool`, `unwrap_or(false)` — fehlen
beide Felder, verhält sich die Funktion exakt wie vorher). Fehlerbedingung
geändert von `exit_code != 0` auf `exit_code != 0 && !killed_by_output_limit`:
ein durchs Ausgabelimit gekillter Lauf (immer `exit_code == -1`) ist damit nie
mehr ein Fehler; ein echter git-Fehlschlag ohne Kill bleibt einer. Ist
`truncated || killed_by_output_limit`, hängt die Funktion an den vorhandenen
(gekürzten) Text den Hinweis `"\n[Diff gekürzt bei 64 KiB:
shell.exec-Ausgabegrenze erreicht]"` an (64 KiB = `DEFAULT_MAX_OUTPUT_BYTES`,
`exec.rs:595`, `ShellToolProvider::new()` in `diff.rs:266` verwendet genau
diesen Default). Moduldoku (`diff.rs:39-49`) entsprechend erweitert.
