# W2A-05 — G-009: `/permissions` auf `ApprovalModeCell` umstellen

- Welle: W2a
- Basis-Commit: 3333441 (W1)
- Agent: W2A-05
- Datei: `harw-ops/src/permissions.rs`

## Änderung

- Alle sieben Nutzungen von `harw_extension_api::approval_mode::current()`/
  `::set()` (Produktivcode Z. 77/123, Tests Z. 211/280/287/337/350 im
  Alt-Stand) ersetzt durch `ctx.service::<ApprovalModeCell>()`
  (`harw_extension_api::approval_mode::ApprovalModeCell`), analog zum
  bestehenden Muster in `mode.rs` (`ctx.service::<SharedSessionController>()`
  → `OpError::NotAvailable` bei fehlendem Service).
- `show`-Zweig: liest `active` jetzt über `cell.get()`; fehlt die Cell in der
  `ServiceMap`, liefert die Operation `OpError::NotAvailable` (neue Konstante
  `NO_APPROVAL_MODE_CELL`) statt eines Modus.
- `set_mode` bekommt `ctx: &OpContext` als zusätzliches Argument (Aufrufer in
  `permissions()` angepasst). Reihenfolge bewusst: erst Argument-Validierung
  (`InvalidArguments` bei fehlendem/unbekanntem Namen, unverändert), danach
  erst der Cell-Zugriff (`NotAvailable` bei fehlender Cell) — ein
  Tippfehler im Modusnamen bleibt unabhängig davon meldbar, ob eine Cell
  registriert ist.
- `cell.set(mode)` wirkt nur auf die Cell dieser `ServiceMap`/Session, nie
  prozessweit — Rückmeldetext ergänzt um „(nur für diese Sitzung)".
- Moduldoku (Kopf) um Abschnitt „Woher der Modus kommt" ergänzt: Operation
  besitzt keinen eigenen Zustand, liest/schreibt ausschließlich die
  `ApprovalModeCell` aus der `ServiceMap`, `set full` wirkt nur für die
  Session, fehlende Cell → `NotAvailable`. Kein „prozessweit" mehr in der
  Doku (war vorher auch nicht explizit behauptet, jetzt aber ausdrücklich
  verneint). Docstring von `set_mode` ebenso ergänzt (`ctx`-Argument,
  `NotAvailable`-Fehlerfall).
- Tests komplett auf lokale, pro-Test-Cells umgestellt statt globalem
  `MODE_TEST_LOCK`/`approval_mode::set`/`::current()`:
  - `test_context()`: leere `ServiceMap`, keine Cell — jetzt mit
    Lauf-eindeutiger Workspace-Wurzel (Atomic-Counter + PID, wie
    `mode.rs::test_context`) statt einem fest verdrahteten, geteilten Pfad,
    damit Tests parallel laufen dürfen.
  - Neuer Helfer `test_context_with_mode(mode) -> (OpContext, ApprovalModeCell)`:
    baut eine frische `ApprovalModeCell` mit Startwert `mode`, legt einen
    Klon in die `ServiceMap`, gibt den Kontext und die (mit der Map geteilte)
    Cell zurück — analog zu `mode.rs::test_context_with_controller`.
  - `permissions_show_and_default_render_deterministically`,
    `permissions_show_lists_all_modes_and_marks_the_active_one`: nutzen jetzt
    `test_context_with_mode`, kein globaler Lock mehr nötig.
  - `permissions_set_full_switches_only_this_cell_and_reports_it` (vormals
    `..._switches_the_mode_and_reports_it`): prüft zusätzlich, dass eine
    zweite, unabhängige `ApprovalModeCell` von `set` unberührt bleibt —
    Beleg für „nur diese Session".
  - Neu: `permissions_show_without_a_cell_is_not_available` und
    `permissions_set_without_a_cell_is_not_available` — fehlende Cell führt
    in beiden Unterkommandos zu `OpError::NotAvailable` mit Text, der
    `"ApprovalModeCell"` enthält.
  - `permissions_set_without_mode_returns_invalid_arguments` und
    `permissions_set_unknown_mode_returns_invalid_arguments` unverändert in
    der Aussage, laufen weiterhin gegen `test_context()` ohne Cell — belegt,
    dass Argument-Fehler vor dem Cell-Check gemeldet werden.
  - `permissions_rejects_capability_mutation` unverändert (betrifft `revoke`,
    nicht den Freigabemodus).

Keine globalen Testzustände mehr in dieser Datei: kein `static … Mutex`, kein
Aufruf von `approval_mode::current()`/`::set()`. Keine Platzhalter, kein
`#[allow(...)]`.

## Registrierung der Cell (Hinweis für Folge-Wellen)

Diese Operation registriert die `ApprovalModeCell` nicht selbst — sie liest
sie nur aus der `ServiceMap`, die eine Kompositionswurzel bereitstellt.
**Wer die Cell tatsächlich in die `ServiceMap` legt (TUI-Command, One-Shot-
CLI, Web), ist nicht Teil dieses Mandats.** Laut Auftrag übernimmt das
W2B-04/W2C (RuntimeServices). Bis dahin liefert `/permissions` in jeder
Laufzeit, die noch keine Cell registriert, `NotAvailable` — das ist so
gewollt (kein stiller Fallback auf einen Standardmodus) und keine
Regression dieses Agenten.
