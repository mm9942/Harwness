## 0. Ausgangslage

`FlatIndex::build` liefert seit W9-C4-W10-L1 `Result<Self, IndexError>`. Der Vorknoten (W10-L1-F) hat
alle Produktions- und Testcode-Aufrufer migriert, aber zwei echte (nicht `no_run`/`ignore` markierte)
```rust-Fence-Doctests in `harw-lens-query` explizit außerhalb seines Owned-Scopes gelassen:

- `harw-lens-query/src/query.rs:68` (Moduldoc von `query.rs`)
- `harw-lens-query/src/lib.rs:92` (Crate-Moduldoc)

Beide enthielten identisch:
```rust
let index = FlatIndex::build(manifest, vec![(chunk, embedding)]);
```
— ohne `?` oder `.expect(...)`, Typfehler-Kompilierfehler sobald `cargo test --doc -p harw-lens-query`
bzw. `cargo doc --no-deps` wieder ausführbar ist.

## 1. Stilermittlung (Brief erlaubt `?`/`fn main`-Muster **oder** „Stil anderer Doctests der Crate")

`FlatIndex::build` selbst wird in seiner definierenden Crate `harw-lens-index` in **jedem** Doctest
(Moduldoc `flat.rs:1-67`, Methode `flat.rs:184-200`, sowie die Testsektion) einheitlich mit
`.expect("…")` behandelt, nie mit dem `?`/`# fn main() -> Result<…> { … # Ok(()) }`-Muster. Das ist die
tatsächlich etablierte Konvention für genau diesen Aufruf im gesamten Workspace (auch von W10-L1-F für
den migrierten Test-Helfer in `query.rs:370` gewählt: `.expect("test embeddings share a single dimension")`).
Entscheidung: `.expect("consistent embedding dimension")` — identische Formulierung wie
`flat.rs:63` (`.expect("consistent embedding dimension")`), um Stilkonsistenz mit der definierenden Crate
herzustellen statt eine zweite, in dieser Codebasis sonst nirgends verwendete Doctest-Konvention
einzuführen.
