## Concrete publication defects and changes

1. **No CI admission gate.** The original Release workflow could publish after
   compilation without checking the blocked CI run. The new gate requires an
   explicitly supplied full manual CI run, the exact candidate SHA and repository,
   successful completion of every required job and execution of its substantive
   steps. Missing/skipped/cancelled/failed checks are rejected. Dispatch event and
   workflow SHAs must match the checked-out tag commit.
2. **Tag push automatically published; Make bypassed verification.** Tag pushes
   and default manual runs now only validate. Publication is an explicit dispatch
   from the tag with `publish=true`. `make release-publish` fails with guidance.
   Existing releases/drafts are never overwritten. The tag is re-resolved before
   release creation, and publication requires dated release notes.
3. **Build success was treated as platform evidence.** Both Linux architectures
   now build and execute their packaged installer, CLI, runner capabilities,
   compiled-agent verification, admission and offline model path natively.
   The finalized source asset must separately build/install through the default
   source installer. These jobs have been added, **not executed here**.
4. **Incomplete assets were not checked explicitly.** Promotion requires both
   Linux archives plus one source archive, exact checksum coverage, the four
   Linux executables (`harw`, `killer`, `harw-job-exec`, `harw-agent-runner`),
   executable permissions, README and both licenses, safe archive members and
   the installer's 512 MiB limit. Build sidecars are checked before aggregation;
   received SHA256SUMS are verified, never silently regenerated.
5. **GitHub/R2 had different release contents.** Source and final SHA256SUMS
   were generated only in the mirror; it downloaded build artifacts instead of
   the published GitHub asset set. Source is now generated once into the final
   bundle and also published to GitHub. The mirror downloads GitHub assets and
   compares the original bundle's checksum file before upload. Source is encoded
   as strict ustar without Git's pax metadata; the existing shell installer
   tolerated Git pax through tar, so this is contract normalization, not a claim
   that its previous source path always failed.
6. **Missing R2 configuration silently appeared successful.** Previously only
   R2_ACCOUNT_ID guarded steps; missing ID skipped everything, missing key pairs
   failed after GitHub publication. All three credentials are now mandatory
   before publication. Their actual presence/permissions are not verified by this
   audit. Bucket, prefix, public route and write credentials still need a real run.
7. **No delivery readback.** The mirror now checks byte identity through S3 and
   public HTTPS before changing discovery files; installer delivery is checked
   before `version.json`/`latest`. A failed readback leaves these pointers alone.
   Publication runs are serialized. Mutable discovery writes are sequential,
   not an atomic transaction; failure after one pointer changes must be reported
   as incomplete and recovered, never labelled a verified release.

## Build and installation support

| Target/path | Previous pipeline | Proposed release requirement |
| --- | --- | --- |
| Linux x86_64 GNU | Native compile, no packaged execution | Mandatory native release build, complete archive, installer and runner/agent smoke |
| Linux ARM64 GNU | Cross-compile, no execution of packaged bytes | Mandatory native ARM64 runner with the same package/installer/runner smoke |
| Android ARM64 / Termux | Experimental cross-build allowed to fail, successful archives could be published | Cross-build experiment retained; no promoted Android asset until real Termux execution is an enforced gate |
| Default source installer | Offline tests used mocked compiler/make; source archive existed only on R2 | Same checksum-protected source on GitHub/R2; real source install smoke before publication |
| `harw update` | GitHub latest release + SHA256SUMS, strict archive validation | Archive naming, root directory and binary layout retained; new source asset is additive |
| macOS | Darwin CI jobs, no macOS release asset | Existing Darwin CI remains mandatory evidence; no new binary support claim |
| Homebrew | `packaging/harw.rb` is a TODO template with example.invalid URL, zero digest and old example version | Not a supported v0.10.0 publication path; do not publish the template |

Native Linux runner success proves that runner image, not all glibc versions,
Raspberry Pi kernel/page-size combinations, privileged cgroups, eBPF or physical
Termux devices. Offline echo does not exercise every sandboxed tool/privileged
operation. Those capabilities retain their own platform/security acceptance
requirements; do not advertise them as verified from a package smoke alone.

## Required gates, in order

1. Integrate/review these fixes and date the 0.10.0 changelog. Freeze one candidate
   commit. Any code or workflow change invalidates prior exact-commit evidence.
2. Resolve the Actions account block and obtain one successful **full manual CI**
   run on that commit. Required: both Linux workspace jobs including doctests and
   six architecture gates; package-scoped DoD; cargo-deny; actionlint; Darwin job
   checks; real native-agent build. Ignored tests remain explicitly ignored.
3. Only after review, create the matching tag on that commit. Tag validation must
   build both native Linux release packages, run their packaged execution checks,
   produce/validate the final bundle and build/install its source archive.
4. Configure R2_ACCOUNT_ID, R2_ACCESS_KEY_ID and R2_SECRET_ACCESS_KEY with access
   to bucket `harw`, prefix `harw`; verify that `https://get.harw.dev/harw` serves
   that route. This audit did not inspect secret values or change cloud resources.
5. Explicitly dispatch Release **on the tag**, using `publish=true` and the
   exact-commit `ci_run_id`. CI evidence and tag identity are rechecked immediately
   before creation. No unchecked local override is provided.
6. GitHub assets must match the finalized bundle. R2 S3 and public downloads must
   match those same bytes before discovery promotion. The complete workflow,
   including mirror/public verification, must succeed before the distribution is
   called verified. Record the CI/release run URLs, commit and SHA256SUMS.

If GitHub creation succeeds but mirror delivery fails, GitHub is published while
R2 is **incomplete**. Fix the environmental fault and rerun **only failed mirror
jobs in the same workflow run** while its original `release-bundle` artifact is
retained. Do not start a new release dispatch or regenerate archives: existing
release refusal protects published bytes. If artifacts expired or the tag moved,
stop and investigate; there is no automatic overwrite/recovery bypass.

Repository guards do not prevent an administrator from manually publishing
through GitHub's UI/API or running old unguarded workflows on historical tags.
No account settings, repository rulesets, existing tags or releases were changed.
